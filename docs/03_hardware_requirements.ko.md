# 하드웨어 요구사항 — Boltz-2 오라클에 왜 ≥24 GB GPU가 필요한가

이 문서는 in-loop 결합 오라클(Boltz-2로 MMP9 + DNA 압타머를 co-fold)이 왜
NVIDIA **T400** 같은 4 GB GPU에서 돌아가지 **않는지**를 원리부터 유도하고,
실제로 필요한 최소 사양을 제시한다. 모든 숫자는 (1) 실측이거나, (2) 명시된
아키텍처 상수이거나, (3) 직접 다시 계산할 수 있는 수식이다.

> 요약 — co-fold 메모리는 **모든 토큰 쌍(N×N) 표현**과 **N³에 비례해 커지는
> triangle 연산 중간 텐서**가 지배한다. 우리 복합체(N ≈ 200–370 토큰)에서는
> 살아있는 활성값이 **수십 GB**에 달하고, 고정 비용(CUDA 컨텍스트 + 가중치 +
> 윈도우 디스플레이)만으로도 4 GB의 대부분이 계산 시작 전에 이미 소진된다.
> 4 GB T400은 실용 바닥선(약 24 GB)에 **6~10배** 못 미친다. 설령 메모리가
> 맞더라도 ~1.6 FP32-TFLOPS의 연산력으로는 수백 번의 co-fold 루프가 몇 주가
> 걸린다. 결론: 4 GB는 "느리지만 됨"이 아니라 **"안 돎"**이다. ≥24 GB급
> 데이터센터/워크스테이션 GPU가 필요하다.

## 1. 측정된 출발점

사용자 워크스테이션 실측(`nvidia-smi`, 2026-07-21):

```
NVIDIA-SMI 595.79   Driver 595.79   CUDA 13.2
GPU 0: NVIDIA T400 4GB   WDDM   657MiB / 4096MiB used   P8
```

여기서 확정되는 사실:

| 항목 | 값 | 의미 |
|---|---|---|
| 전체 VRAM | 4096 MiB (4 GB) | 절대 상한 |
| 이미 사용 중 | 657 MiB | 이 카드가 **화면 출력**도 겸함(WDDM) |
| 드라이버 모델 | WDDM (TCC 아님) | OS 예약 추가 + 가용 메모리 예측 어려움 |
| 등급 | Turing TU117, CUDA 코어 384개, 이 작업에 쓸 텐서코어 경로 없음 | ~1.6 FP32 TFLOPS |

즉 계산에 **실제로 쓸 수 있는** 예산은 4 GB보다 한참 적다 — 현실적으로
**약 2.5~3.4 GB**이고, 데스크톱 부하가 걸리면 WDDM이 더 회수해 간다.

## 2. co-fold 모델이 메모리 바운드인 이유 (메커니즘)

Boltz-2와 AlphaFold3는 **pairformer / triangle-attention** 아키텍처다.
O(N) 은닉 상태만 들고 다니는 서열 모델과 달리, 이들은 **모든 토큰 쌍**의
관계를 명시적으로 저장한다. 여기서 토큰은 단백질 잔기 1개 또는 뉴클레오타이드
1개다.

기호:

- `N`  = 전체 토큰 수 (단백질 잔기 + DNA 염기)
- `c_z` = 쌍 표현 채널 수 ≈ **128**
- `c_m` = MSA 채널 수 ≈ **256**
- `S`   = 유지하는 MSA 행 수(subsample), 보통 수백
- `H`   = 어텐션 헤드 수 ≈ **4**
- `b`   = 원소당 바이트 (fp32 = 4, bf16/fp16 = 2)

메모리를 좌우하는 세 가지 구조:

### 2.1 쌍 표현 — 저장, O(N²)
`[N, N, c_z]` 형태 텐서. 사본 1개:

```
mem_pair = N² · c_z · b
```

### 2.2 Triangle attention — 전이(중간) 텐서, O(N³)
쌍 표현은 *triangle attention*으로 갱신된다. 쌍 (i,j)의 갱신이 제3의 인덱스
k 전체에 대해 어텐션을 건다. 순진한 구현의 어텐션 로짓 텐서는 `[H, N, N, N]`:

```
mem_tri = H · N³ · b
```

이 N³ 항이 가장 격렬하다. 실제 구현(Boltz 포함)은 이걸 **청킹(chunking)**해서
`[N,N,N]` 전체를 한 번에 만들지 않고 **메모리를 시간과 맞바꾼다**. 하지만
청킹해도 블록마다 큰 `[N,N,·]` 중간 텐서가 여러 개 살아있고, pairformer 블록이
**수십 개 쌓여** 있어 각 블록이 다음 블록용 입력을 계속 붙들고 있다.

### 2.3 MSA 스택 + diffusion — 추가 배수
- MSA 표현 `[S, N, c_m]`, MSA 모듈 안에 사본이 여러 개 살아있음.
- 구조는 **diffusion** 모듈이 생성하는데, 여러 개의 구조를 **샘플링**(기본값
  수 개)하고 **recycling** 반복을 돈다 — 각각이 피크 메모리에 배수로 곱해진다.

따라서 피크 VRAM은 개략적으로:

```
Peak ≈ Fixed(컨텍스트 + 가중치 + 디스플레이)
     + k1·(N²·c_z·b)             ← 깊이 전반의 쌍 표현 사본 다수
     + k2·(N³급 triangle 연산)   ← 청킹돼도 크고 블록마다 반복
     + k3·(S·N·c_m·b)            ← MSA 스택
     + k4·(samples · atoms)      ← diffusion
```

여기서 `k` 배수는 네트워크 깊이와 살아있는 버퍼 수에서 나온다. 핵심은
**N에 대한 초선형 증가**다 — 복합체 크기를 2배로 하면 지배 항은 4배 이상 늘어난다.

## 3. *우리* 복합체 대입

MMP9 촉매 도메인(UniProt P14780, 잔기 107–443) = **337 aa**; FnII 제거 "mini"
구조 = **162 aa**; DNA 압타머 ≈ **35 nt**.

| 구조 | N (토큰) |
|---|---|
| full 촉매 + 압타머 | 337 + 35 = **372** |
| FnII 제거 mini + 압타머 | 162 + 35 = **197** |

### 3.1 쌍 표현 사본 1개 `N²·c_z·b`

| N | fp32 | bf16 |
|---|---|---|
| 197 | 19.9 MB | 9.9 MB |
| 372 | 70.8 MB | 35.4 MB |

하나만 보면 작다 — 하지만 이런 사본이 스택 전반에 **여러 개** 살아있다.

### 3.2 순진한 triangle 로짓 텐서 1개 `H·N³·b` (fp32, H=4)

| N | H·N³·b |
|---|---|
| 197 | **0.12 GB** |
| 372 | **0.82 GB** |

이건 수십 개 블록 중 **하나**의, 두 triangle-attention 연산 중 **하나**의,
**단일** 중간 텐서다. 그래서 청킹과 반정밀도를 써도 *합산* 피크는 이 크기의
복합체에서 실제 사용자들이 보고하는 **~16–40 GB** 범위에 들어간다. (AF3 자체
가이드도 수십 GB, 큰 핵산계는 80 GB까지 언급한다. Boltz-2의 단백질–DNA co-fold
실용 바닥선은 ~24 GB — 이 레포의 `docs/02_improved_method.md` 하드웨어 표.)

---

## 4. 4 GB 예산 대조

활성값을 하나 할당하기도 전에, 4 GB T400은 이미 다음을 들고 있어야 한다:

| 고정 비용 | 추정 |
|---|---|
| CUDA + cuDNN 컨텍스트 | 0.5 – 1.0 GB |
| Boltz-2 가중치(로드) | ~1 – 2 GB |
| 윈도우 디스플레이(WDDM, 실측) | 0.66 GB |
| **고정 소계** | **~2.2 – 3.7 GB** |

남는 건 활성값용으로 **≈ 0.3 – 1.5 GB**, 필요량은 **수십 GB**다. 이 격차는
플래그 하나로 없앨 몇 퍼센트가 아니라 **10~100배(1~2 자릿수)**다.

```
필요(활성값)        ~16,000–40,000 MB
T400 고정비용 후 가용   ~300–1,500 MB
                      ───────────────────
부족분                 ~10×–100×
```

결과: 두 구조 모두 기본 설정에서 첫 pairformer/triangle 패스 중에
`torch.cuda.OutOfMemoryError: CUDA out of memory`.

## 5. 두 번째 벽: 연산 처리량

가령 저메모리 청킹으로 *mini* 구조가 메모리에 겨우 들어갔다고 치자. 그러면
이번엔 연산이 발목을 잡는다:

| GPU | FP32 TFLOPS (근사) | 상대값 |
|---|---|---|
| T400 (Turing TU117) | ~1.6 | 1× |
| RTX 4090 | ~82 | ~50× |
| A100 80 GB | ~19.5 FP32 / ~312 TF32 | ~12×–200× |

A100에서 (MSA 캐시 시) ~1–3분 걸리는 co-fold 한 번이 T400에서는
**수십 분~수 시간**이 된다. 그런데 closed loop(`src/pipeline/closed_loop.py`)는
오라클을 **수백~수천 번**(`rounds × pop`) 호출한다. 예컨대 720회면
**수 주의 실제 시간**이고, 매 호출마다 OOM 위험이 있다. 비현실적이다.

---

## 6. 4 GB 카드로 *되는* 것

공정하게 짚자면, 4 GB가 이 모델에 아예 쓸모없는 건 아니다 — 다만 *이* 타깃에는
한참 못 미친다. N³/N² 스케일링 때문에 **작은** 계만 들어간다:

| 계 크기 | 4 GB 가능성 |
|---|---|
| N ≲ 80–100 (짧은 단량체 / 작은 펩타이드) | 저메모리 설정이면 종종 가능 |
| N ≈ 197 (mini MMP9 + 압타머) | 어려움; 극단적 저메모리로만, 매우 느림 |
| N ≈ 372 (full MMP9 + 압타머) | 불가 |

우리 타깃은 4 GB가 선택지에서 빠지는 지점을 한참 넘어선다.

## 7. 최소 실용 사양

`docs/02_improved_method.md`(하드웨어 표)를 위 메커니즘과 맞추면:

| 단계 | 최소 | 여유 |
|---|---|---|
| **Boltz-2 in-loop 오라클 (Stage 3)** | 1× GPU **24 GB** (RTX 4090 / L40 / A5000) | 1× A100 40 GB |
| AF3 핵산 컨센서스 (Stage 4) | 1× A100/H100 **80 GB** | H100 80 GB |
| MD + MM/GBSA (Stage 5) | RTX 4090 24 GB | A100 |
| 시스템 RAM / 디스크 | 64 GB / ~50 GB 여유(가중치+MSA 캐시) | 128 GB / 1 TB |

≥24 GB GPU를 구하는 실용적 방법:

- **클라우드 대여**(가장 빠름): RunPod, Vast.ai, Lambda, 또는 Colab(A100).
  24–80 GB 리눅스 박스를 띄우면 `scripts/run_on_gpu.sh`가 Stage-3 루프 전체를 돈다.
- **워크스테이션 GPU**: RTX 4090 / A5000 / A6000 등.
- 윈도우라면 **WSL2**(레포의 `.sh`/Makefile은 POSIX 셸 필요) 또는 네이티브
  리눅스 호스트. CUDA-on-WSL2는 윈도우 NVIDIA 드라이버를 그대로 상속한다.

## 8. 경험적으로 검증하는 법 (믿지 말고 확인)

후보 GPU에서 전체 실행에 들어가기 전에:

```bash
# 1. 카드와 메모리 확인
nvidia-smi --query-gpu=name,memory.total,memory.free --format=csv

# 2. co-fold 한 번 시도하며 메모리가 끝까지 오르는지(완료 or OOM) 관찰
bash scripts/run_on_gpu.sh        # step 3이 단일 스모크 테스트 co-fold
# 다른 터미널에서:
nvidia-smi dmon -s m              # 실시간 메모리 모니터
```

4 GB T400에서 예상 결과는 첫 triangle-attention 패스 중 `CUDA out of memory` —
이 분석에 대한 결정적이고 비용 없는 확인이다.

## 9. 막히지 *않는* 것

파이프라인의 CPU 검증 절반은 영향받지 않으며 이미 커밋돼 있다: 프래그먼트
라이브러리, DNA 폴딩/스코어링, 충실한 AiDTA assembler, `StructureProxyOracle`
closed loop, 그리고 `results/candidates.json`의 구조-prior 랭킹 쇼트리스트.
이들은 어떤 머신에서든 돈다. **결합** 오라클(Stage 3+)만 ≥24 GB GPU가 필요하고,
그 하드웨어가 준비되면 한 플래그(`--oracle boltz2`) 교체로 끝난다.

# 코드 전수 점검 기록 (GPU 대기 중 수행)

GPU 할당을 기다리는 동안 전 코드를 점검하고 발견한 결함을 수정했습니다.
**실제로 GPU에서 돌 때 터지거나, 조용히 잘못된 결과를 내는 문제**에 집중했습니다.

## 발견·수정한 결함 (심각도 순)

### 1. fragment 귀속(attribution) 오류 — 학습을 무력화 ★가장 심각
`closed_loop.py`가 "엘리트 후보가 어떤 fragment를 썼는지"를 **문자열 검색**으로
역추적했습니다. 3-mer는 서열 어디에나 우연히 매칭되므로:

| | 실제 사용 | 검색으로 추정 | 오탐 |
|---|---|---|---|
| 실측(5개 조립 샘플) | 27개 | 116개 | **+337%** |

즉 가중치 갱신이 **거의 노이즈**를 학습하고 있었습니다. 이 프로젝트의 핵심인
"닫힌 루프"가 사실상 작동하지 않는 상태였습니다.

**수정**: `weighted_assemble()`이 조립하면서 **실제 fragment 인덱스를 기록**하고,
그 값이 사전필터·채점·체크포인트를 통과해 가중치 갱신에 쓰이도록 변경.
검증 결과 후보당 2~6개로 정확해졌습니다.

### 2. 균등화(smoothing) 스케일 오류 — 탐색 조기 종료
가중치 갱신식에서 데이터 항은 `t × len(pool)`(평균 1 스케일)인데 균등화 항은
`1/len(pool)`이라 **44배 작았습니다**. 시뮬레이션 결과 미사용 fragment가
**6라운드 만에 하한(0.05)으로 붕괴** → 탐색이 죽고 국소최적에 갇힘.

**수정**: 균등화 항을 같은 스케일(1.0)로. 수정 후 실측 가중치 하한이 **0.301**로
유지되어 탐색이 살아 있음을 확인.

### 3. Boltz 인터페이스 점수 추출 실패 — 조용한 신호 손실
Boltz는 `pair_chains_iptm`을 **체인 인덱스 문자열(`"0"/"1"`)**로 키잉하는데,
코드는 YAML에 지정한 `"A"/"B"`를 찾았습니다. 항상 실패해 **더 약한 전역 ipTM으로
조용히 후퇴**했습니다(예: 0.77 대신 0.60). 오라클 품질이 직접 저하됩니다.

또 `iptm or complex_iptm` 패턴은 `iptm=0.0`(정당한 값)을 falsy로 처리해 잘못된
값을 채택할 수 있었습니다.

**수정**: 두 표기 모두 시도 → 실패 시 2체인 행렬의 비대각 원소 사용, `or` 대신
명시적 `None` 검사. 어느 경로를 썼는지 `used` 필드로 기록. 6개 시나리오 전부 통과.

### 4. 최종 리포트 크래시 — 파이프라인 맨 끝에서 폭발
`report.py`의 정렬이 `dict.get(key, 0.0)`을 썼는데, **키가 있고 값이 `null`**이면
`None`을 반환합니다. MM/GBSA가 실패한 후보는 `dG`가 `null`로 기록되므로,
**그런 후보가 하나만 있어도** `float < NoneType` 예외로 리포트 생성이 실패합니다.
모든 비싼 단계를 마친 뒤 마지막에 터지는 최악의 위치입니다.

**수정**: `None` 안전 접근자 도입. `null` 섞인 입력으로 재검증 완료.

### 5. `RESUME=0`이 무시됨
`${RESUME:+--resume}`는 "비어 있지 않으면"이라 `RESUME=0`에서도 `--resume`을
전달했습니다. 새로 시작하려는 의도가 조용히 무시됩니다.
**수정**: `[ "$RESUME" = "1" ]` 명시 비교.

## 성능·견고성 개선

- **접촉 계산 벡터화**: 순수 파이썬 이중 루프 → numpy. 현실적 기하(대부분 비접촉)
  기준 **8배** 빠름. 접촉 집합이 기존과 완전히 동일함을 검증.
- **MM/GBSA 힘장 실패 진단**: 템플릿 매칭 실패 시 문제 잔기명과 DNA 명명 규칙을
  안내(OpenMM 원본 traceback 대신).
- **`setup_server.sh` 제거**: 이 클러스터는 `setup_login.sh` + `slurm_run.sh`
  워크플로이므로, 잘못된 안내를 하던 단일서버용 스크립트와 참조를 정리.

## 검증했고 문제 없던 것

- **MM/GBSA 원자 인덱스 정합성** — OpenMM은 topology 순서로 인덱스를 부여하고
  `Modeller.delete()`가 상대 순서를 보존하므로, `sorted(keep)`이 부분계 원자
  순서와 일치. 단일궤적 분해가 좌표 정합적임.
- **캘리브레이션 게이트** — 3개 시나리오(PASS 0.91 / FAIL 0.42 / 프록시 0.99)
  모두 정확히 판정. **프록시 오라클은 AUROC가 아무리 높아도 차단**.
- **가짜 점수 방지** — boltz·chai_lab 미설치 시 명확한 에러로 중단(점수 생성 안 함).
- **셸 조건부 인자** — `run_refine.sh`의 `USE_CHAI` 구문이 `set -e`에서 안전.
- **heredoc 변수 확장** — `slurm_run.sh`에서 제출 시점 확장(`$STAGE`, `$RECEPTOR`)과
  런타임 확장(`\$SLURM_SUBMIT_DIR`)이 의도대로 분리됨.
- **CSV 스키마 호환** — 파일럿 출력을 `consensus.py`가 정상적으로 읽음.

## 통합 검증 결과

- 파이썬 모듈 16개 문법·임포트 **전부 OK**
- 셸 스크립트 4개 문법 **전부 OK**
- CLI 9개 인자 파싱 **전부 OK**
- **연속 실행(8라운드 × 40후보 + 재개 2라운드)**: 학습이 단조 개선
  (best 0.9330 → 0.9706 → 0.9781), 재개 정상, 산출물 무결성 확인,
  fragment 추적 누락 0건

## 남은 미검증 영역 (GPU 필요)

아래는 이 환경에 GPU·boltz·openmm이 없어 **실제 실행으로는 확인 불가**합니다.
정적 검증과 방어 코드는 넣었지만, 첫 GPU 실행에서 확인이 필요합니다.

1. **Boltz 실제 출력 스키마** — confidence JSON 키 이름, PDB/CIF 파일 경로 패턴.
   파싱은 여러 스키마를 시도하도록 했으나 실물 확인 필요.
2. **MSA 캐시 추출** — `make_msa.py`가 Boltz가 생성한 정렬 파일을 찾는 경로.
   실패 시 자동으로 `--use_msa_server`로 후퇴(느리지만 동작).
3. **OpenMM 힘장 매칭** — Boltz PDB의 DNA 잔기 명명이 amber14 템플릿과 맞는지.
   실패 시 진단 메시지 출력.
4. **Chai-1 API** — `run_inference` 반환 객체의 점수 필드.

이들은 모두 **실패해도 조용히 잘못된 결과를 내지 않고 멈추거나 후퇴**하도록
설계했습니다.

# 2차 점검 — 독립 코드리뷰에서 추가 발견 (같은 밤)

1차 점검 후 **적대적 관점의 독립 리뷰**를 별도로 돌려 교차 검증했습니다.
1차에서 놓친 문제가 여럿 나왔고, 직접 재현·검증한 뒤 모두 수정했습니다.

## 조용히 틀린 결과를 내던 문제 (가장 위험)

### A. 잔기 번호 매핑 붕괴 → FnII 지표가 정반대
`fetch_receptor.py`가 헤더를 `>MMP9_catalytic`로만 써서 범위 정보가 없었고,
`consensus.py`는 이를 파싱 실패해 **스칼라 오프셋 107**로 폴백했습니다.

- `catalytic`(연속 구간)은 **우연히** 맞았습니다.
- `catalytic_nofn`은 **불연속**(107–215 + 391–443)이라 어떤 스칼라 오프셋도 틀립니다.

실측: FnII를 제거한 구조에서 **촉매 아연자리(His401/405/411) 접촉이
"FnII 100%"로 보고**됐습니다. 활성화 위험 지표가 완전히 뒤집힌 상태였습니다.

**수정**: `mmp9.py`의 `DOMAIN_SPECS`를 단일 진실원으로 삼고, 헤더에 범위를
명시(`>MMP9_catalytic|107-443`), `consensus.py`는 **명시적 local→UniProt 인덱스
리스트**를 사용. 길이 불일치 시 즉시 중단. 검증 후 fnII_fraction = 0.0 (정상).

### B. Boltz가 이전 결과를 재사용 → 다른 서열의 점수를 반환
모든 호출이 `input.yaml`이라는 같은 이름을 썼습니다. Boltz는 **같은 출력
디렉터리에 이미 처리된 record가 있으면 건너뛰고 정상 종료**합니다. 재실행 시
**직전 서열의 점수와 구조를 그대로 반환**하게 됩니다. `consensus.py`는
후보별 고정 경로를 쓰므로 재실행에서 실제로 발생합니다.

**수정**: 입력 파일명을 **서열 해시**로, `--override` 추가, confidence JSON을
**stem으로 매칭**. 오라클이 자기 구조 경로를 직접 반환하도록 해서 소비자가
공유 디렉터리를 뒤지지 않게 함.

### C. MSA 캐시가 수용체와 무관하게 재사용
단일 고정 파일명이라 337aa용 정렬을 162aa 수용체에 그대로 넘길 수 있었고,
경로가 CWD 상대라 다른 위치에서 실행하면 캐시를 놓치고 공개 MSA 서버를
반복 호출(차단 위험)했습니다.
**수정**: **수용체 서열 해시로 키잉**, 저장소 루트 기준 경로.

## 크래시 (테스트 못 한 경로)

- **Chai-1이 매 호출 실패**: `chai_lab`은 출력 디렉터리가 **비어 있어야** 하는데
  우리가 만들고 입력 파일까지 넣었습니다. Stage 4가 조용히 Boltz 단독으로
  퇴화 — "독립 2차 모델"이라는 근거 자체가 사라집니다. → 별도 하위 디렉터리로 분리.
- **Chai 결과 정렬 안 함**: `ranking_data[0]`은 정렬 전이라 임의 샘플. → `.sorted()`.
- **죽은 폴백 코드**: Chai는 `.json`이 아니라 `.npz`를 씁니다. 실패 시 0.0을
  "측정값"인 양 반환했습니다. → npz 판독, 없으면 명확히 예외.
- **에너지 단계가 mmCIF를 못 읽음**: Chai 출력이 `.cif`인데 `PDBFile`만 사용. → `PDBxFile` 분기.

## 과학적 타당성

### D. 캘리브레이션이 잘못된 분자를 검사하고 있었음
양성 대조군 F3B는 **2′-F 피리미딘 RNA** 압타머인데 `U→T`로 바꿔 **DNA로
공동접힘**했습니다. A-form vs B-form — 다른 분자입니다. **정상적인 오라클이
이 잘못된 분자를 랜덤 DNA보다 낮게 매겨도 이상하지 않습니다.**

게다가 양성이 1개뿐이라 AUROC가 1/12 단위로 양자화돼 분산이 큽니다.
`run_pilot.sh`가 이 값으로 **하드 게이트**를 걸어, 우연한 실패로 하루치 GPU
할당을 통째로 날릴 수 있었습니다.

**수정**:
- Boltz YAML에 **RNA 엔티티** 지원 추가 → F3B를 **RNA로** 채점
- 음성 대조군도 **양성과 같은 화학종·길이**로 생성(화학종 차이가 아니라 결합을 측정)
- `--seeds`(기본 3)로 **시드 간 편차** 측정
- **분리 z-score** 병기, AUROC와 함께 게이트
- 요약에 **"양성이 1개뿐이라 한계가 있다"**는 경고를 명시적으로 기록
- 실패 시 `FORCE=1` 우회로를 제공하되, **"결과가 미검증"임을 경고**

## 자원 낭비

- **GPU 2장 요청, 1장만 사용** → 기본값 1장으로 (센터가 낭비를 제재)
- **임시 디렉터리 무한 증가**: 후보마다 MSA·텐서·로그 트리가 남아 파일럿에서
  수백 개 누적 → 채점 후 자동 정리
- **사전필터 탈락 후보 영구 차단**: 가중치가 바뀐 뒤에도 재시도 불가였음 →
  `attempted`와 `seen`을 분리(실측: attempted 320 vs scored 160)

## 에너지 단계 정밀화

- **`--only-pass` 누락** → 합의 탈락 후보에도 MD를 돌리고 있었음. 연결.
- **가장 낙관적인 포즈 선택** → Stage 4의 취지를 무효화. **합의 접촉 집합과 가장
  일치하는 포즈**를 선택하도록 변경.
- **평형화 없음** → 최소화 직후 속도 0에서 시작. Maxwell-Boltzmann 속도 부여 +
  워밍업 후 샘플링.
- **오차 과소평가** → 상관된 스냅샷을 독립으로 취급. `sd` 병기하고 sem을
  **"하한"**으로 명시.

## 리뷰가 "문제 없음"으로 확인해 준 것

- MM/GBSA 단일궤적 분해의 **좌표 정합성** (1차 점검 결론과 일치)
- 셸 조건부 인자(`RESUME`, `USE_CHAI`)와 heredoc 변수 확장 시점
- 접촉 계산 numpy 재작성의 정확성
- 수정된 가중치 갱신식 — 4라운드 후 합계가 정확히 pool 크기(44), 붕괴/폭주 없음

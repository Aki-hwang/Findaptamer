# 왜 GPU가 필요한가 — 특히 왜 24GB인가 (한글 요약)

이 프로젝트가 "논문(AiDTA)보다 정확한" 이유는 **생성된 압타머를 실제로 단백질과
공동접힘(co-folding)시켜 결합 신호로 평가하는 오라클**을 생성 루프 안에 넣기
때문입니다. 바로 이 오라클 단계가 GPU를 필요로 합니다. CPU만으로는 구조 점수까지만
가능하고(지금 샌드박스 상태), **결합 예측은 불가능**합니다.

## 1. 어떤 단계가 GPU를 쓰나

| 단계 | 하는 일 | GPU 필요? |
|---|---|---|
| Stage 0–1 | 표적 준비, fragment 라이브러리, HDOCK 도킹 | ❌ CPU |
| **Stage 3** | **Boltz-2 공동접힘 오라클** (압타머+MMP9 → 인터페이스 ipTM) | ✅ **핵심** |
| Stage 4 | AF3 합의(consensus) 재접힘 | ✅ (80GB) |
| Stage 5 | MD + MM/GBSA 에너지 계산 | ✅ (24GB로 충분) |

## 2. 왜 하필 24GB인가 (기술적 이유)

AlphaFold3·Boltz-2 같은 공동접힘 모델의 GPU 메모리는 **토큰 수의 제곱(≈ N²)** 으로
늘어납니다. 여기서 토큰 = 단백질 잔기 + 핵산 염기(+ 원자). 이유는 모델이 모든
토큰 쌍(pair) 사이의 관계를 담는 **pair representation** 과 어텐션을 유지하기
때문입니다.

우리 복합체 크기:
- MMP9 촉매 도메인 ≈ **170~450 잔기** (수용체 범위 선택에 따라)
- DNA 압타머 ≈ **30~60 염기**

이 규모의 단백질–DNA 복합체를 Boltz-2로 **구조(pose)만 예측**할 때 실측 VRAM
사용량이 대략 **24~40GB** 구간입니다. 그래서:

- **24GB (RTX 4090 / L40 / A5000)** = Boltz-2를 이 복합체 크기에서 **OOM(메모리
  초과) 없이 돌릴 수 있는 실용적 최소 사양**. 아래로 내려가면(예: 16GB) 압타머가
  길거나 수용체 범위를 넓히면 메모리 초과로 터집니다.
- 24GB면 **Stage 3(Boltz-2 오라클) + Stage 5(MD/MM-GBSA)** 를 다 돌릴 수 있어
  **개선 루프 전체를 Boltz-2 단일 오라클로 완주**할 수 있습니다.
- **80GB (A100/H100)** 가 따로 필요한 건 **AF3**입니다. AF3는 핵산 표적에서 약
  5,120 토큰·**80GB**를 권장하고, N² 특성상 24GB로는 핵산 복합체를 못 올립니다.
  단, AF3는 Stage 4(합의)용 **선택 사항**이고, 라이선스도 **비상업용**입니다.

## 3. 결론 — 워크스테이션 사양 권장

| 목적 | 최소 | 이상적 |
|---|---|---|
| 개선 루프 전체(Boltz-2 오라클 + MD) | **RTX 4090 24GB** + RAM 64GB + 디스크 1TB | A100 40GB |
| AF3 합의까지 추가 | — | **A100/H100 80GB** |

**핵심 한 줄:** 24GB는 "논문을 이기는 핵심 단계(Boltz-2 결합 오라클)"를
상업적으로 안전한 MIT 스택으로 **완주할 수 있는 최소 사양**이고, 80GB는 AF3
합의라는 **정확도 보강(선택)** 을 위해서만 추가로 필요합니다.

> 참고: Boltz-2 = MIT 라이선스(상업 사용 가능), AF3 = 가중치 요청·**비상업**.
> 그래서 실제 제품화를 염두에 두면 24GB + Boltz-2 조합이 가장 실용적입니다.
